# Codex · Harness Bridge

Notes specific to using Harness Bridge with [OpenAI Codex](https://openai.com/codex) (CLI / IDE integrations).

## Instructions file
- **Path:** `AGENTS.md` at repo root.
- **Loaded:** automatically on session start (Codex's documented convention).
- **Install behavior:** `prompts/init.md` appends a `## Harness Bridge — keep .harness/bridge.md current` section.

## Init / Producer / Consumer / Recover / Uninstall
- **With MCP:** use the tools (`templates/codex/config.toml`).
- **Skills:** `harness-bridge install-skills --agent codex` installs them to `~/.agents/skills`, which the ChatGPT desktop app also reads. Invoke them with `$recover-session`, or ask in plain language.
- **Without either:** paste the prompts.

## Transcript location (for recovery)
- **Path:** `$CODEX_HOME` (default `~/.codex`) `/sessions/YYYY/MM/DD/rollout-<timestamp>-<uuid>.jsonl`, plus `archived_sessions/`. Line 1 is `session_meta`, which holds `id`, `cwd` and `git`. Titles come from `session_index.jsonl`.
- **Layouts** (verified on codex-cli 0.164; Harness Bridge picks one per file so turns are never double-counted):
  - **items** (Codex Desktop): `event_msg/item_completed` with `UserMessage`, `AgentMessage`, `CommandExecution` (incl. `exit_code`), `FileChange` and `ContextCompaction`.
  - **legacy:** `event_msg` `user_message`/`agent_message`, plus `response_item` `function_call` (`shell`, `apply_patch`, `update_plan`) with their outputs.
- **Stop reasons:** `turn_aborted` (interrupted); `error` events whose text names a usage/rate limit; `token_count.rate_limits` at 100%.
- **Never treated as the user's request:** injected `<environment_context>` / AGENTS.md messages.

## Native resume and launch
- **Resume:** `codex resume <session-id>`.
- **Continue a recovered session:** `codex -C <repo> '<prompt>'`. Generated by `harness-bridge recover <id> --to codex`.

## Skills
Install the `handoff`, `pickup`, `recover-session` and `harness-bridge` skills (invoke them the way this agent invokes skills) with `npx skills@latest add codemeall/harness-bridge` or `npx -y @codemeall/harness-bridge install-skills --agent codex`. Where the agent does not support skills, paste the prompts instead.

## Known quirks
- Codex's `AGENTS.md` convention is well-aligned with Harness Bridge's instructions-file approach. The maintainer snippet drops in cleanly.
- Codex tool surface differs from Claude Code in detail (patch semantics, command execution), but Harness Bridge only requires file read + file edit, which all variants support.

## Round-trip status
- **Verified:** Codex as the destination of a recovered Claude Code session. In two real `codex exec` runs (read-only), Codex discovered and recovered the session itself with the CLI, restated verified vs claimed state, and waited for confirmation. See `tests/round-trip.md`, Test G.
- **Tested with fixtures only:** Codex as the recovery source (both layouts).
